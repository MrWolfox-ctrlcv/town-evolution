# V6 有效冷任务续做（2026-11-07）

`f7d2e47` 的热缓存解决了已完成区块的回访，但镜头请求集合一变，`V6SurfaceChunks.request()` 仍无条件取消当前任务。本次只修正这个取消条件，不增加缓存，不改变地图或网格精度。

## 保留条件与边界

- 当前整组任务必须仍被请求，且每块的局部版本、细节档、远景误差和邻边签名全部匹配。条件满足时，沿用同一海岸/逐格/合并迭代器、staging 账本及待上传事务，不重新开始。
- 整组保留或整组取消，不拆开编辑/接缝原子组。已完成的组成员也参与校验。新请求涉及的其它脏块继续排队；提交当前组不会清除其它块的 dirty 状态。
- 任一块离场、LOD/邻边/误差失配仍取消整组；移除区块的空网格事务不能被当成构造任务续用。编辑、资源/海岸/树脚变化、显式 abort 和 dispose 继续走原取消路径，旧事务提交仍抛出 Stale。
- 未完成构造和未完成上传仍不可拾取或用于支撑。兼容请求保持事务身份，因此正式 view 不会取消已上传的隐藏部分；完整上传后仍按原顺序原子发布网格、支撑和拾取。
- 不保存离场半成品，没有新增缓存池、条目或字节额度。只让已有一组工作活到完成；仍受原 256 MiB 保守准入总账限制，失败/取消/销毁释放 staging。该账本不是浏览器堆或显存测量。
- 为遵守仓库每个 TypeScript 文件最多300行的规则，原邻块偏移常量移到现有 `V6SurfaceJobs.ts`，取值和用法不变。

## 同口径计数

基线为 `f7d2e47` 的隔离编译输出；改动后使用同一脚本、seed 42173、同一10块真实地图、树脚精细格、20次合成请求、每次512步。时间上限设为 Infinity，使计数不受机器并发/3ms切片影响；因此这些结果不能与此前3ms基准直接算提速比例。测试选取10块不改变游戏的全岛请求策略。

原始记录：`benchmarks/v6-cold-work-20261107.json`。

### A保持有效、远处B的近景请求反复切换

- 总已完成格补片构造：**6,400 → 2,816，减少56%**。
- 被后续请求丢弃的已完成格补片：**5,120 → 1,536，减少70%**。余下丢弃发生在确实失效的B目标上。
- A的1,280格细节及接缝组由“停止后才完成”变为“移动中完成”。移动阶段发布6个事务，其中只有1个包含新构造，其余是已有快照的零构造事务。
- 停止后新增格构造：**1,280 → 0**；固定步数推进调用9 → 1。不是帧率或耗时结果。
- 全过程总上传仍为928,104字节、17次Mesh创建；只是更早完成，未减少最终几何。
- 最终10块几何/属性/三角归属 SHA-256完全相同：`6de0acf359c9e04fa17f7beb6b0f86aa2f3524b489118b94270ce5fcdfdc3a84`。
- 最终总账均为21,014,284字节；全过程峰值均为28,324,188字节。续做版在移动阶段更早达到该峰值，基线在停止后达到。销毁后resident与staging均为0，全部模拟Mesh恰好销毁一次。

### A/B目标互换，整组签名确实失效

基线和修改版计数完全一致：总构造6,144格、丢弃4,864格，移动中没有新组发布。此情况需要取消，不会为了降低计数而发布过期LOD或接缝。
