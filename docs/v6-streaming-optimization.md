# V6 远景构造与调度优化（2026-11-07）

本次是 CPU 构造、重复采样和调度优化，不是缩地图，也没有放宽地形 LOD 误差。没有修改存档、资源数量、地形业务规则或近景挖填/拾取权威。

## 实现

- 原始未编辑的远景精细回退增加直接晶格写入。只有真实 V6 预备采样、当前资源与原始资源相同、邻接可拥有单元的 cap 相同且没有编辑时才允许。保留原始四分之一格三角面、Float32 位置、法线及逐三角草/石材边界；常量平面、树脚精细面、修改资源、裁切和墙仍走原通用路径。远景仍不包含可交互资源 ID。
- 海岸法线反复访问相同邻域，现缓存原始 height/color 查询。缓存局限于该海岸 source，FIFO 最多 4,096 项；不缓存编辑状态或网格。回收 source 即释放，逐出仅引发重算。
- 首块排序基于实际视域而非固定岛中心；随后精细块排在背景块之前。成员相同但视域改变时刷新后续优先顺序，不取消已经完成的隐藏事务。
- 每帧最多处理四组事务，共享原有构造步数、上传字节及构造/上传毫秒预算，不把每组当成一帧强制等待。默认构造和上传各 3ms，均为软预算。每个编辑/接缝组仍隐藏上传、整体发布；中途取消或失败仍不发布局部网格。
- 构造步数及实际上传字节现在显式回报，便于剩余预算扣减。独立审查指出的“时间退出仍多计一步”已修复并加入零毫秒测试。

## 验证边界

- 独立审查对 seed 1937 全地图的 13,177 个快路可接受单元（其中 5,407 格包含石材）逐个展开三角面；位置、法线和颜色逐项 Object.is 相同，去除远景 resourceId 后的元数据相同。
- 新增/扩展测试覆盖真实预备世界与通用写入等价、编辑/资源边界回退、视域顺序、已暂存事务不因纯排序取消、每帧四组上限、共享步骤/字节/时间预算、缓存隔离/逐出和零时间计数。
- 上传测试使用 Cocos 调用替身检查字节预算、隐藏 staging、失败和取消。它们不测真实 GPU 上传耗时。
- 采样缓存有明确容量上限，但其 JS 对象开销不计入现有地表网格 admission 账本。该账本并非实测 JS 堆或显存。

## 复现 CPU 对照

先执行 `npm run build:domain`，再执行 `node scripts/benchmark-v6-streaming.cjs`。可用 `V6_SURFACE_BUILD` 选择隔离的旧/新编译目录，用 `V6_BENCHMARK_OUTPUT` 保存 JSON。

基准沿用 seed 42173、196 块、最大远景高度误差 0.25、树脚精细保留、每次 advance 最多 512 步/3ms，并保持旧岛中心排序以使构造耗时可比。它分别记录世界准备、海岸准备、网格构造、上传分片 CPU 复制及规范化几何哈希。哈希生成不计入构造/分片计时。

输出里的 30/60Hz 秒数只是假设每帧一次 advance 的旧调度估算。它没有模拟新批调度，也不是浏览器实际加载时间。

## 本次结果

云端 Node 24.22.1 / AMD EPYC 9V74 CPU 对照，三组顺序旧/新运行（原始记录见 `benchmarks/v6-streaming-20261107.json`）：

- 全岛网格构造中位数 **4,323.45ms → 3,220.35ms，减少约25.5%**。旧版范围4,277.21–4,598.47ms，新版3,137.99–3,632.87ms。这不是浏览器首次可用时间。
- `advance` 调用中位数 **1,520 → 1,165**，沿用旧式每次最多512步/3ms的独立构造基准。实际帧批调度另由预算测试覆盖，没有伪造GPU吞吐或实机加载时间。
- 前两组与最终专项验证部分重叠，不参与以上中位数；原始数字仍保留。
- 五组旧/新全岛规范化几何 SHA-256 均为 `6998feb3f48188756b6378186ee2cf93d9fb7b902ec1b1d5b4e5b49b9a1bb95e`。196块、339,013三角、289,511顶点、313上传片、16,014,270源上传字节均不变；单片最大65,532字节。
- `npm run check` 通过，2,183项测试、官方Cocos类型检查、项目/架构和222个资产检查均通过。最终受影响的47项专项测试再次通过，`npm run demo:domain`通过。
- 多轮中单次构造仍可能超过3ms，毫秒预算仍是软预算。世界准备约4秒量级，未在本次加速。
