# terrain6 准备取消后的菜单返回

## 已复现的问题

在 `eb426a6` 上，通过真实 `GameStart` 和 `startMenu` 动作复现：

- 游戏设置 → 重新开始 → 取消准备，错误返回游戏，而非设置。
- 设置 → 存档 → 待验证手动栏位 → 取消准备，错误返回游戏，而非存档。
- 标题 → 自然挖填实验 → 取消 → 存档 → 重新开始 → 取消准备，错误返回标题，而非存档。

`GameStart.back()` 原来只对确认页、栏位页、存档页处理返回位置。准备页落入默认分支，因此取消一个加载动作会连带关闭原菜单。原有准备任务已经正确取消；这是菜单导航问题，不是已发生的数据丢失。

新增 7 个定向测试在修改前有 6 个失败。标题取消本来正常，作为保留行为一并验证。

## 最小修改

`GameStart` 记录本次准备的来源页，取消时恢复它。若切镇已经释放旧会话，不能回到没有会话的游戏或设置页，此时回到标题。

成功完成仍使用该次准备捕获的局部来源页；嵌套的主存档/备份准备会独立保存下一次来源，不被外层完成回调覆盖。原有任务取消与代次检查保持不变，后续帧不会重新执行已取消任务。

页面类型与无会话回退规则抽到 14 行的 `StartNavigation.ts`，`GameStart` 仍导出原类型，保持现有接口和每个源码文件不超过 300 行的规则。

未修改地形生成、几何、拾取、素材、资源释放、缓存上限、存档格式、存储锁或写入方法。新增状态只有一个页面名称，不持有世界数据或新资源。
