# V6 首次加载时保留相机操作

首次真实地形尚未发布时，鼠标滚轮已经改变相机，但它会结束当前手势。`V6TownNavigation` 原先只看这一帧是否仍有触点，因此没有记住滚轮操作；第一块真实地形发布后，启动时排队的全岛浏览会覆盖玩家选择。两次导航 tick 之间完成的平移、双指缩放也有同样缺口。

生产 `MapCamera` 滚轮监听器和 `V6TownNavigation` 的定向复现：起始 zoom 为 0.0625，滚轮 +100 后为 0.051170672067373864；旧代码在首块发布后跳到 zoom 1、焦点 (96,96)。修改后保留玩家的 zoom 与焦点 (6,6)。这是解析相机替身下的源码流程验证，不是真实画面或加载耗时测量。

## 最小修复

相机只在用户平移或缩放实际改变焦点/zoom 时增加一个导航计数；导航层比较计数，取消尚未执行的启动全岛浏览。程序性 reset、layout、overview、HUD zoom 本身不增加计数，它们仍由既有显式导航意图处理。无效、零、视口外、被 UI 遮挡及已到缩放边界且相机不动的滚轮不增加计数。

明确请求全岛浏览或重置导航时，先接收当前计数，避免早先未被 tick 读取的操作覆盖更新的明确请求。此后发生的实际相机操作仍能取消待执行请求。持续触摸和工具操作仍保留原有门禁。

为了维持每份 TypeScript 源码不超过 300 行（含结尾分隔）的结构规则，`dispose` 复用已有 `resetInput`，`tick` 改为单行委托；不改变清理顺序或手势逻辑。没有改变地形精度、就绪判定、缓存预算、存档或业务规则。
