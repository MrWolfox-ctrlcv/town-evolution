# terrain6 自然挖填实验：接入状态与限制

[项目介绍](../README.md) · [完整代码树](code-tree.md) · [v5 边界](v5-integration.md) · [09:01 历史开发快照](terrain6-development-snapshot.md)

这是 **2026-11-06 的 terrain6 源码集成候选**。它已经进入本仓库 `assets/scripts/`，不再只是仓库旁的研究原型；仍未作为在线试玩版本发布，也没有完成真实 Cocos / WebGL 画面、GPU 或手机验收。

## 版本与试玩状态

- 当前在线试玩检查点为 **v31**，包含原有 v5 预览、木桥、堆肥木桶和烤制路线，不包含本次 terrain6。在线包和本次 Git 源码必须分别验收；更新源码不等于重新发布试玩。
- 普通小镇与演示岛新建时仍为 terrain4。原 `v5-preview` / `v5-bridge-demo` 入口、既有 v1–v5 生成规则和保存语义不因 terrain6 改变。
- 新入口为 **自然挖填实验**，profile 是 `v6-preview`，存储 key 包含独立 revision `v6-natural-grass-edits-1`。不要通过改 v5 常量、清空旧档或覆盖旧 key 来载入新地形。
- 保存仍使用 **schema10**；terrainVersion、地形 revision 和 `terrain6.format = 1` 是额外约束，不是 schema10 的所有旧地图都变成 terrain6。
- 未知版本 / revision、损坏档案保留原始数据。实验新局、读取、备份与手动存档准备完成后，才创建会话并进行完整导入校验。

## 已进入主游戏源码的部分

### 自然地貌与规则改造

`domain/v6-*` 提供 192×192 世界、自然起伏、真实资源、公共 Float32 格点、海岸 / 水系和分步构造。普通高地与自然资源柱分开，未编辑地貌保持自然形态；挖填产生公共层面与格边竖直切面，不把全山预先做成人工台阶。

- `v6-edit-plan.ts` 统一预览与提交条件，`actions/terrain6-edit.ts` 在命令克隆中提交。
- 天然坡可以直接挖低或填高。挖掘平面不得高于原格最低点；填筑平面不得低于原格最高点，避免一次动作暗中免费做反向改造。
- 编辑需空出目标上的树、建筑 / 农田、地堆和掉落，保留水域 / 岸边 / 自然港缓冲。海上扩地不借用内陆挖填入口。
- 未改邻格的自然面不随编辑平滑；人工土石和被覆盖的天然资源分开保存，暴露后仍按同一依据采集，不伪造自然 `nX_Z` ID。

### 真实土石，而非临时研究 token

terrain6 将既有 `soil` / `stone` 接入真实库存、地堆、掉落、拾取、拆分与合并。当前候选单位为 **1 格 × 1 个名义公共层**，最小份额为 **1/4096**。

- 实际三角面厚度经裁切积分后量化。混合层共享一个体积预算，不给土、石各发一整份；正的极薄资源和填筑缺口保留至少一个量化单位。
- 这是有限精度实验经济，不是无限精度物理体积，也不是已确定的最终价格。没有隐藏可花费材料账本或新增 token。
- 挖出的土石先成为真实地面掉落，明确拾取才入仓。填筑消耗明确选中的库存或地堆快照，不寻找别处材料；UI 当前的挖填工具从所选土 / 石库存取料。
- 失败、过期操作或空间不足保持原状态、材料和编号。旧 v1–v5 的整数材料与旧配方不变，9 土 → 1 泥、9 泥 → 1 格海上扩地仍是旧规则；泥不作为内陆体积材料。

### 按格检查点与保存上限

`v6-save.ts` 保存每格初始资源剩余量、最低裁切面、当前层高、保留填层与单调操作号。正式路径不使用仓外原型的逐操作 journal，也没有“最多 4096 次编辑”的寿命上限。载入按几何重建最终状态，不重放产物发放。

现有保存格式上限仍为 **4,000,000 个 JSON 字符**。所有 v6 命令在发布成功状态之前检查完整序列化长度；超限原子回滚，不先扣料或留下只能在内存存在的新进度。此保护不等于解决浏览器 localStorage 配额、权限或磁盘失败。复杂填层仍可能使存档达到格式上限；紧凑格式尚未实现。

### 高程、渲染、拾取与输入

- v6 建筑 `baseElevation` 从完整足迹的真实平面派生，放置、移动、旋转、合成和导入校验共用规则；旧地图不额外写入这个字段。
- 农田 / 作物、附件、树脚、掉落与支撑查询接入实际高程。源码包含实际地形 ray 命中、遮挡和触控路由，不能将源码 / Node 测试称作真机触摸通过。
- `V6Surface*` / `V6Coast*` 生成分块表面；`V6IslandView` / `V6ChunkMeshes` / `V6TreeView` 管理地形和真实保存树。取消或过期任务不能发布半份新面；编辑邻块的渲染、拾取和支撑需一致提交。
- 新实验提供挖地、填地、开田模式，以及回家、缩放和全岛浏览。未就绪、远景浏览和细化中的地块有状态提示，不能把未显示 / 未发布的细节当作可操作目标。

上述是集成范围，不是对所有渲染、输入、取消 / 恢复和设备场景的最终通过声明。

## 尚未完成的部分

### terrain6 木桥仍关闭

v6 的木桥装配和桥存档导入保留明确安全 gate，界面提示使用已有木桥演示岛。旧 v5 木桥不受影响。仓库旁的高桩桥实验没有被接入本批；文件中存在支柱几何工具不等于 v6 桥已可用。

原因是两岸真实坡高不能继续套用旧桥固定桥面。完整两端支撑、桥面、进桥坡道 / 台阶、附加占地、可达性和保存重算仍需一起验收，不能靠抬高桥面隐藏穿岸问题。

### 性能尚未达成流畅体验目标

- 世界准备是可取消的分步工作，但总 CPU 工作仍为秒级；软预算不是硬帧时上限，GC、同步导入 / 保存及不可切分步骤仍可能卡顿。
- 全岛远景、局部精细表面、远树与输入门禁是不同阶段；出现远景不代表细节已就绪，也不证明全链路已在几秒内完成。
- 显示内存使用 256 MiB 的保守记账准入上限，覆盖旧面与暂存面相关逻辑成本，不是浏览器进程、GPU 或驱动实际内存上限。树及其他场景物体不包含在地表账本内。
- 每份 v6 网格上传源数据有分片限制；逻辑缓冲字节量、常驻 MeshRenderer 数量、理论 60 Hz 调度下界不能当作 GPU 显存、实际 draw calls 或实测 FPS。
- 超出显示预算会取消暂存并提示调整视域，不能删除存档编辑来“优化”性能。具体极端档案、回收和重试仍需目标设备验收。

09:26 UTC 冻结源码的纯CPU观测：正常seed42173全岛远景累计CPU约4.386秒；按每60Hz帧调用一次调度器，首个真实地块下界为0.317秒，全岛为25.517秒。这不是浏览器实测加载时间，也仍未达到“几秒全岛齐备”。逻辑上传为15.27MiB、313个上传部分，不是GPU显存或屏幕draw calls。

合法极端检查点包含2304个编辑格，其中1152格为64层、存档2,790,856字符；显示预算拒绝超限暂存后清零，移动到真实36块相机视域可恢复，保存SHA不变。最终观测的最大单步CPU为8.34毫秒，不构成硬帧时或手机性能保证。该档案是合法导入的压力样本，不宣称材料来自正常经营。

上述覆盖面与测量定义必须保留；不沿用更早的中间性能数，也不把离线 Blender 图片当作 Cocos 游戏截图。
