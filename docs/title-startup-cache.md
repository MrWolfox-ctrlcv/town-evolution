# 固定标题模板的启动缓存

## 测量与取舍

本轮从 2026-11-08 保全的第三版源码恢复到独立目录，未改验收基线、已保全归档或已发布资源。已有图标延迟加载/共享纹理、标题手册首次打开构造及 release 压缩保持不变。

对实际启动代码做了五次独立 Node 冷进程测量，而非只看测试数量：

- 原始固定标题模板每次都运行 `createDemoGame`。最新对照的创建中位数为 **1021.34 ms**，加上模块加载为 **1025.51 ms**。另一次独立五次测量为953.68 ms，说明结果有正常机器负载波动。
- CPU profile 显示一次约906 ms的生成中，候选位置生成/排序约615 ms，占68%。每次放置都创建整张192×192地图的候选，船坞还检查四方向。完整存档校验约16 ms，递归冻结约2.6 ms。
- 首屏仍有更大的独立工作：预览在 `game.init` 前同步转换9份 Effect。编译器、解析器及源块占 release app-esm 的545,893字节（45.73%）。使用真实 Mesa llvmpipe/GLES 软件验证的转换约1898 ms，其中JavaScript及其它工作约1501 ms，驱动调用约303 ms；32次Shader编译及16次链接成功。此值不是浏览器或硬件GPU时延。
- Effect 转换的展开结果达3.43MB，需要额外无损打包与构建缓存管理。因此本轮优先落地更小、更独立且不涉及Shader的固定标题模板缓存。Effect构建期转换只保留调查证据，没有混入本轮实现。

## 实现与保持不变的内容

`TitleSnapshot.ts` 是从当前 `createDemoGame(TITLE_ISLAND_TIME)` 自动生成的JSON字符串，不是截图、简化场景或玩家存档。每次 `titleIsland()` 都重新解析并递归冻结，保持原先独立对象的契约。场景仍经原来的 `TownView`、模型、材质、相机和风动渲染。

快照的每个字段均与当前生成器深等，包含32栋建筑、192棵树和1372块自然资源。未改素材、玩法、生成器、存档格式、图片尺寸、GPU纹理或网格预算。可玩演示岛仍由正常流程生成，标题不会读写玩家数据。

最新五个冷进程的缓存后创建中位数为 **2.38 ms**，连同模块加载为 **3.52 ms**。同一次序列化的SHA256在前后所有进程中一致。

代价是应用包增加静态数据。相同release esbuild配置下：

| 应用阶段       |  原始字节 |  gzip 9 |  Brotli |
| -------------- | --------: | ------: | ------: |
| 缓存前 app-esm | 1,193,757 | 323,336 | 260,778 |
| 缓存后 app-esm | 1,287,236 | 336,017 | 267,448 |
| 增量           |    93,479 |  12,681 |   6,670 |

这些压缩数值是离线计算，不保证实际服务采用对应Content-Encoding。它不代表首帧已提升同样的秒数：网络、Cocos节点构造、纹理加载/上传、Shader运行时编译及实际绘制均仍需要图形环境实测。

## 后续维护

1. 修改演示内容、业务规则或固定标题时钟后，运行 `npm run title:snapshot`。
2. 工具直接编译当前纯业务依赖图，再调用 `createDemoGame`，不会使用旧 `.domain-build` 作为权威输入。即使生成文件丢失或损坏也可重新生成。工具校验固定的 CommonJS 输出路径和 JavaScript 写出选项，并拒绝包括写出失败在内的编译诊断，避免误读旧产物。
3. 审查生成文件，再运行 `npm run check`。不要手改JSON或哈希。
4. 普通检查和预览构建首先核对所有domain源码、标题入口、编译配置及生成工具的哈希。路径排序、文件边界和CRLF归一确保跨平台稳定；生成数据不纳入输入哈希，避免循环，也不写时间戳。
5. 缺失、过期或内容被改时明确失败并提示重新生成，不静默更新、不在玩家运行时回退到昂贵生成器。
6. 内容哈希用于损坏检测，不是语义证明。现有 `title-island.test.cjs` 始终与当前生成器逐字段深等，另有源变更、时钟变更、数据修改、哈希修改和缺失检查。真实的 TypeScript 写出失败、关闭 JavaScript 输出及输出目录变动也有回归，失败时不得覆盖现有模板。

## 验证边界

定向测试覆盖严格存档校验、fresh身份、冻结、作物风动不推进、坏存档隔离，以及标题构造不再调用过程生成器。没有新增依赖，也未更换渲染器。

本轮测量仅为实际纯CPU代码、真实软件GLES编译调查及离线包体对照。没有宣称Creator导入、WebGL画面、Android/手机帧率、网络首屏、GPU内存或发布通过。
