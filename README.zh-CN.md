# 小镇进化 Town Evolution：操作说明

[项目介绍与当前版本边界](README.md) · [完整代码树](docs/code-tree.md) · [预览构建](scripts/preview/README.md)

本文保留玩法操作说明；当前内部状态为 schema10，含围栏/长凳或相应发现的保存文件为 wire schema11，普通小镇 / 演示岛新建时仍为 terrain v4，v5 新岛预览及木桥演示分别保存。terrain6 已作为独立“自然挖填实验”入口接入当前源码，但尚未部署；在线 v31 不包含这次改动。下列历史测试结果只覆盖各自注明的检查点，不证明当前全部改动、GPU 或手机已验收。

[本地检查点：堆叠融合与探索图鉴（2026-11-03）](docs/checkpoint-fusion-2026-11-03.md)：新增建筑材料挂载、锤子扩建、真实发现记录与 ImageGen 素材图鉴。该历史检查点完成了实际 Cocos 桌面及模拟触屏各3轮交互验证；已有正确版本的构建产物时可运行 `npm run preview:serve`。新 clone 须先按预览说明准备工具并构建。

[标题与存档说明](docs/start-and-saves.md)：标题以独立的演示岛实机渲染为背景，不改玩家进度，可开始或继续小镇、管理存档、查看图鉴，也可选择独立的[演示岛](docs/demo-island.md)。
以 **Cocos Creator 3.8.8 + TypeScript** 实现的模块化建筑经营原型，目标是同一套业务规则支持网页与 Android 独立应用。

**玩法闭环**：购买作物 → 逐格种植 → 地面掉落 / 手动收进田箱 → 明确取回入库 → 商店销售 / 批量订单 / 海岸装船 → 扩建农田和仓房。

## 工具与地面产品基础

- 左侧为工具，右侧为产品；透明图标分别翻页，不遮住整条地图。
- 工具暂时无限耐久，侧栏显示 ∞；旧存档即使耐久为0也可正常使用，不扣耐久、不花钱补给。肥料仍显示实际份数且用途未开放；水壶可灌田，也可划过多个土堆合成泥土。锤子可消耗挂载的2份木材扩建仓房。
- 作物有按种类区分的轻微摇曳、生长和成熟弹动，动画不改变九格种收规则。
- 产品拖到空地后松手，每格上限按物品区分：木石6、泥土9、四种作物10，其余5份；点选地面堆叠可收回 1 份。
- 地面堆叠可长按抬起、移动或同类合并（填满该产品上限后，余量留原地）；所有产品都可拖到仓库或左右任一侧栏的可见图标/翻页控件，松手整堆回收，容量不足则整堆留原地。从侧栏拖出的工具、库存图标拖回两侧只结束拖动，不增加数量，也不撤销已经完成的播种或收割。非法落点及多指取消会复位；建筑可按“转向”切换四个方向。
- 泥土用逐份堆叠模型表达，9份组成完整3×3泥块；拖到相邻岸边水格可扩1格地，保护船坞出口。泥土拖到基础房屋挂载1份，再用锤子制成住宅，不增加未约定的人口或经济功能。旧配方仍为9土经水壶制成1泥，9泥整堆填1格合法近岸地；terrain6 另以真实土 / 石体积的1/4096份额结算，仍为实验候选平衡，不改写这套旧泥土配方。
- 挖掘工具拖到平地开垦小田；三块同类小田排成L形后拖放合成大田，作物与生长进度保留；水壶可将两种尺寸的空田灌成水田；胡萝卜、小麦、生菜只能种在旱田，水稻只能种在水田；有作物时须先收获。旧档已有作物不会被删除。详见[农田升级](docs/farmland-upgrades.md)与[泥土扩地](docs/mud-expansion.md)。
- 挖土、采石和普通田镰刀收割后，产物留在原处地上，可长按移动、与同类地堆互叠；不会自动入仓或飞向侧栏。带箱田仍须手动用镰刀，作物直接进入独立16份田箱，箱满保留成熟作物。明确拾取、取箱货或购买后才有入仓飞行动画，失败操作不播放。
- 斧子拖到树上松手获得木材；木材必须从产品栏拖到地上，再按手册配方使用工具。建成后多余木材退回库存。
- 右下角配方文件夹打开目录，选择后抽出单张配方纸；纸可拖动、缩放和收起，主界面不常驻展示配方。[当前目录](docs/recipe-handbook.md)与现役配方表同步，旧冷藏融合不占目录、页码或发现进度，已有存档记录仍保留。
- “工具”页显示无限耐久提示并保留种树入口，不再展示工具补给。启动时保留旧版不兼容存档，只有用户主动重置才替换主档并保留重置前备份；演示岛与正常小镇独立保存。

## 自然挖填实验（terrain6）

标题中的“自然挖填实验”使用独立 `v6-preview` 存档。选择挖地、填地或开田后拖动工具，预览实际耗料 / 产出，松手提交单格操作；取消不扣料。天然坡可直接挖低或补到公共平面，挖出的土石先落地，须明确拾取入仓。不可编辑水岸、保留地或被建筑、树、地堆和掉落占用的格子。

地形准备与加载显示阶段提示，可取消；回家与缩放用于返回可操作细节区。远景不代表当前地块已可操作。v6 已接入高差木桥：将两座栈桥对齐放在真实河流的完整干岸上，直接拖放合成宽 2 格、总长 7–16 格的桥；两端各 2 格坡道位于原栈桥占地内，桥面和桩按真实地形重建，不削平河岸。超过高差 / 坡度限制，跨海湖、已有挖填 / 填海或占用时拒绝操作；移动、转向与读档也重新校验。原有“木桥演示”仍为 v5 独立存档。高差桥尚未发布，源码中的触控与高程接入不能视为真实 Cocos / WebGL、GPU 或手机验收。详情和保存 / 性能边界见 [terrain6 接入状态](docs/terrain6-integration.md)。

## 当前本地版本

已加入1木材+锯子→围栏、2木材+锯子→长凳；各占1格，支持选择、旋转、移动与保存，暂无居民休息加成或围合系统。成品拖到侧栏安全取消，不拆成木材，也尚无整件入仓。

新增育苗、石磨/磨坊、石窑/烘焙坊、运输仓和木栈桥路线。石窑使用地上明确选中的1木+1石+锤，不暗扣仓库。船坞由木栈桥、箱子、公告牌三件用锤子装配，保留旧船坞和旧航次。当前 schema10 还包含空箱锤击变堆肥木桶、显式投料 / 等待原料取回 / 肥料领取，以及石窑2胡萝卜烤成1份烤胡萝卜；肥料份数有限，用途尚未开放。木桥在 v5 中由两岸栈桥拖放合成，并有独立“木桥演示”入口。详细规则见[新生产路线](docs/new-production-routes.md)与[堆肥、烤制、木桥](docs/compost-roast-bridge-design.md)。

- 左侧工具与右侧产品均透明悬浮，没有整条底色。拖蔬菜划过空的小格播种，拖镰刀划过成熟的小格收获。
- 地图跟随拖动，双指或滚轮缩放；建筑长按约 0.4 秒抬起后跟随拖动，松手到空地移动，到兼容建筑设施直接合体；建筑与箱子、公告牌、推车等物体须用锤子明确选中组合。
- 用1木和锤子制作订单板后批量交付；商店提供买卖，船坞提供装货、取回、发船和领取。
- 库存图标每次拖动只转移 **1 份**：拖到商店卖出，拖到船坞装货。面板可选 1、4 或全部。
- 每块田有 3×3 个独立小格，每格播种消耗 1 份蔬菜，成熟后收获 2 份；冷藏菜不能播种。新局提供 1 份蔬菜，装货不直接获得金币。

胡萝卜、小麦、生菜、水稻均可直接购买、逐格种植和收获，左右工具与产品使用真实透明图片。冷藏加工不再作为新玩法入口。船坞必须位于当前种子的真实水缘，不能建在内陆。

源码中包含旱田三作物与水稻、临水建造及独立存档测试；当前状态须以同一份最终源码运行的检查日志为准。下方历史浏览器验证只对应列出的旧提交，不能替代 schema10、木桥和新地形的实际浏览器验收。完整规则见[交易设施说明](docs/commerce-mvp.md)。

## 快速检查源码

需要 Node.js 22 或更新版本：

```sh
npm ci --ignore-scripts
npm run check
npm run demo:domain
```

`check` 检查业务类型、官方 Cocos API 类型、测试、场景引用、依赖方向与循环依赖。`demo:domain` 演示完整业务操作，不渲染画面。

## 用 Creator 打开试玩

1. 在 Windows 或 macOS 安装 **Cocos Creator 3.8.8**。
2. 将本仓库根目录作为现有项目导入，等待脚本与资源导入结束。
3. 打开 `assets/scenes/Main.scene`，点击预览。场景里的启动组件会生成低模建筑、地图和原生 UI，无需手工摆放每个模型。
4. 拖右侧蔬菜划过初始菜地的小格，每格消耗 1 份，15 秒后拖镰刀划过该格收获 2 份。种苗不足时可在商店或作物入口购买，价格以当前界面为准；订单板通过材料配方制作后可交付订单。
5. 在满足真实水缘与出口条件的海岸，用栈桥、箱子和公告牌明确锤击装配船坞，拖入作物装货，发船后领取收入；建筑长按抬起可移动。
6. 测试存档恢复、满仓提示、重复领取以及网页与手机不同窗口尺寸。

操作设计采用建造预览与确认，经营操作集中在所选建筑的面板；地图可拖动和缩放。最终触屏手感仍需真机检验。

普通新局提供 120 金币、一个基础仓房和一块菜地；单独选择的演示岛另有预建设施与测试资源。基础仓房容量 16；扩容改造后容量 32。演示岛另有固定模板与测试资源；不开放新冷藏加工。数字是短时试玩参数，不是最终运营数值。

## 工程结构

完整文件树、启动链路、地形版本隔离与测试入口见 [docs/code-tree.md](docs/code-tree.md)。以下为简图。

- `assets/scripts/domain/`：纯 TypeScript 规则、配置、网格关系、事务和存档校验。
- `assets/scripts/domain/actions/`：建造、农田、融合、地面物品、加工、堆肥、育苗、运输、交易等原子命令模块。
- `assets/scripts/application/`：可独立测试的会话管理、时钟与存储注入、横竖屏布局计算。
- `assets/scripts/presentation/`：Cocos 启动协调、UI、镜头输入、低模模型与增量场景同步。
- `assets/scripts/art/`：运行时与导出共用的规范模型配方、调色板和网格编译器。
- `art/exports/`：规范 glTF 模型及尺寸、三角形数量等清单；当前数量以 `manifest.json` 为准。
- `assets/scenes/Main.scene`：启动场景。
- `tests/`：正常流程、失败不改状态、重复操作、离线返回、损坏存档与随机操作测试。
- `scripts/`：项目结构与架构检查、命令行规则演示。
- `docs/architecture.md`：早期 MVP 架构背景，其中旧经济和 schema 参数已被后续专题文档替代。
- `docs/verification.md`：已完成的源码与浏览器验证，以及待完成的编辑器、构建和真机验收表。

建筑家族通过共用主体和附件表达差异；首版只做明确配方，不做任意两两融合。初版是本地单机存档，不接账号、广告、支付、服务器经济或跨设备同步。

## 模型资产

[共享建筑演进](docs/art/building-inheritance.md)：基本房、商店与仓库复用同一房门、墙体和瓦顶；同一公告牌成为商店招牌，同一箱体组件组成仓库装卸棚。木纹是实际接入的 image 生成UV材质，3D网格由共享组件实现，并非自动图生3D。

仓房、加工设施、作物阶段、环境道具、地面产品与建筑模块等 glTF 资产，由可编辑 TypeScript 配方生成；完整清单为 `art/exports/manifest.json`。运行时直接使用同一配方，不依赖未验证的 glTF 加载流程。`npm run art:export` 重新导出，`npm run art:check` 检查导出与规范配方完全一致；模型范围与复用方式见[美术说明](docs/art/README.md)。

## 网页与 Android

在 Creator 构建面板选择 Web Mobile，加入 Main 场景并设为启动场景；产物通过 HTTP 服务访问。Android 则先配置该 Creator 版本要求的 SDK、NDK 与 JDK，再生成并构建原生工程，先测试 debug APK。

项目不包含发布签名密钥或平台凭据。TapTap 上架、SDK 接入和资质审核是之后的独立工作。
