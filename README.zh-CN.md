# 小镇进化 Town Evolution

[演示岛与重复测试说明](docs/demo-island.md)：首次进入演示岛，可在工具页切换独立正常小镇。
以 **Cocos Creator 3.8.8 + TypeScript** 实现的模块化建筑经营原型，目标是同一套业务规则支持网页与 Android 独立应用。

**玩法闭环**：购买作物 → 逐格种植 → 收获入库 → 商店销售 / 批量订单 / 海岸装船 → 扩建农田和仓房。

## 工具与地面产品基础

- 左侧为工具，右侧为产品；透明图标分别翻页，不遮住整条地图。
- 镰刀、斧子、锯子成功使用才消耗耐久；水壶、肥料、锤子展示数量，具体用途尚待设计，不会假装生效。
- 作物有按种类区分的轻微摇曳、生长和成熟弹动，动画不改变九格种收规则。
- 产品拖到空地后松手，每格最多 5 份同类产品；点选地面堆叠可收回 1 份。
- 地面堆叠可长按抬起、移动或同类合并（目标最多5份，余量留原地）；拖到仓库或右侧产品栏松手可整堆回收，容量不足不回收、不丢失。非法落点及多指取消会复位；建筑可按“转向”切换四个方向。
- 成功收获、拾取、购买或补充工具后，小图标从实际来源飞向对应侧栏；失败操作不会出现领取动画。
- 斧子拖到树上松手获得木材；木材必须从产品栏拖到地上，再按手册配方使用工具。建成后多余木材退回库存。
- 右下角配方文件夹打开目录，选择后抽出单张配方纸；纸可拖动、缩放和收起，主界面不常驻展示配方。
- 工具补给与种树入口在“工具”页。本次按用户要求清理旧测试进度，演示岛与正常小镇从此独立保存。

## 当前本地版本

- 左侧工具与右侧产品均透明悬浮，没有整条底色。拖蔬菜划过空的小格播种，拖镰刀划过成熟的小格收获。
- 地图跟随拖动，双指或滚轮缩放；建筑长按约 0.4 秒抬起后跟随拖动，松手到空地移动，到兼容建筑合体。
- 建造免费的订单板后批量交付；商店提供买卖，船坞提供装货、取回、发船和领取。
- 库存图标每次拖动只转移 **1 份**：拖到商店卖出，拖到船坞装货。面板可选 1、4 或全部。
- 每块田有 3×3 个独立小格，每格播种消耗 1 份蔬菜，成熟后收获 2 份；冷藏菜不能播种。新局提供 1 份蔬菜，装货不直接获得金币。

胡萝卜、小麦、生菜均可直接购买、逐格种植和收获，左右工具与产品使用真实透明图片。冷藏加工不再作为新玩法入口。船坞必须位于当前种子的真实水缘，不能建在内陆。

新增版本通过本地源码检查，覆盖三作物、临水建造及演示/正常存档隔离。下方历史浏览器验证只对应列出的旧提交；本次新交互和交易设施尚未完成实际浏览器验收。完整规则见[交易设施说明](docs/commerce-mvp.md)。

## 快速检查源码

需要 Node.js 22 或更新版本：

```sh
npm ci --ignore-scripts
npm run check
npm run demo:domain
```

`check` 检查业务类型、官方 Cocos API 类型、测试、场景引用、依赖方向与循环依赖。`demo:domain` 演示完整业务操作，不渲染画面。

## 用 Creator 打开试玩

1. 在 Windows 或 macOS 安装 **Cocos Creator 3.8.8**。
2. 将本仓库根目录作为现有项目导入，等待脚本与资源导入结束。
3. 打开 `assets/scenes/Main.scene`，点击预览。场景里的启动组件会生成低模建筑、地图和原生 UI，无需手工摆放每个模型。
4. 拖右侧蔬菜划过初始菜地的小格，每格消耗 1 份，15 秒后拖镰刀划过该格收获 2 份。种苗不足时可直接花 8 金币购买；建造免费订单板后可交付 8 份蔬菜。
5. 在南侧海岸建造船坞，拖入作物装货，发船后领取收入；建筑长按抬起可移动。
6. 测试存档恢复、满仓提示、重复领取以及网页与手机不同窗口尺寸。

操作设计采用建造预览与确认，经营操作集中在所选建筑的面板；地图可拖动和缩放。最终触屏手感仍需真机检验。

普通新局提供 120 金币、一个基础仓房和一块菜地；默认展示的演示岛另有预建设施与测试资源。基础仓房容量 16；扩容改造后容量 32。演示岛另有固定模板与测试资源；不开放新冷藏加工。数字是短时试玩参数，不是最终运营数值。

## 工程结构

- `assets/scripts/domain/`：纯 TypeScript 规则、配置、网格关系、事务和存档校验。
- `assets/scripts/domain/actions/`：建造改造、生产领取、订单三个独立业务模块。
- `assets/scripts/application/`：可独立测试的会话管理、时钟与存储注入、横竖屏布局计算。
- `assets/scripts/presentation/`：Cocos 启动协调、UI、镜头输入、低模模型与增量场景同步。
- `assets/scripts/art/`：运行时与导出共用的规范模型配方、调色板和网格编译器。
- `art/exports/`：30 个独立 glTF 模型及尺寸、三角形数量等清单。
- `assets/scenes/Main.scene`：启动场景。
- `tests/`：正常流程、失败不改状态、重复操作、离线返回、损坏存档与随机操作测试。
- `scripts/`：项目结构与架构检查、命令行规则演示。
- `docs/architecture.md`：规则与边界。
- `docs/verification.md`：已完成的源码与浏览器验证，以及待完成的编辑器、构建和真机验收表。

建筑家族通过共用主体和附件表达差异；首版只做明确配方，不做任意两两融合。初版是本地单机存档，不接账号、广告、支付、服务器经济或跨设备同步。

## 模型资产

仓房三种形态、制冷设施、三种菜地阶段、环境道具与建筑模块共 30 个 glTF 资产，由可编辑 TypeScript 配方生成。运行时直接使用同一配方，不依赖未验证的 glTF 加载流程。`npm run art:export` 重新导出，`npm run art:check` 检查导出与规范配方完全一致；模型范围与复用方式见[美术说明](docs/art/README.md)。

## 网页与 Android

在 Creator 构建面板选择 Web Mobile，加入 Main 场景并设为启动场景；产物通过 HTTP 服务访问。Android 则先配置该 Creator 版本要求的 SDK、NDK 与 JDK，再生成并构建原生工程，先测试 debug APK。

项目不包含发布签名密钥或平台凭据。TapTap 上架、SDK 接入和资质审核是之后的独立工作。
