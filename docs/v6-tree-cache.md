# terrain6 树区块回访 CPU 缓存（2026-11-07）

基于已交付的完整整合源码 `b8a8f7f`，本次仅减少树区块离场后返回时的重复 CPU 网格构造。保留 Cocos 3.8.8、原地图、树的保存身份、生成外观、LOD、地形高度和精确三角拾取。没有修改领域规则、存档格式、材质、天空、Android 启动或线上站点。

## 实现及边界

- 离场或 LOD 替换后的完整树批次可进入缓存，最多 8 MiB 保守记账、32 个条目。超大批次不缓存；按最早退场顺序淘汰，优先保护当前正在返回的区块。没有无界增长或扩大原地形 256 MiB 账本。
- 这 8 MiB 是**新增的非活跃树 CPU 预算**，不包含仍可见的树、正在上传的树、原始共享树资产、分配器和驱动开销，不是全游戏内存上限。原地形账本本来就不计树。成本按数值数组容量、独立拾取位置、共享索引的保守重复计费及元数据估算，不是实际 JS 堆测量。
- 缓存按区块、树身份/位置/成长阶段、近远景区分。砍树、移动、成长和换种子会移除不匹配缓存。普通库存或树剩余数量变化不会重建相同外观。
- 返回时重新验证所有实际偏移树脚的高程；缓存批次等待上传期间也重新检查，避免发布旧高度。普通新构造和已可见树的原有高程处理不在本次改动范围内。
- 缓存不提供渲染或拾取：离场仍立即销毁 GPU 网格、移除拾取。返回仍经过原地面就绪检查、隐藏分片上传及原子发布。没有新增显存常驻，也没有降低上传预算。取消和销毁释放原持有者，缓存转入 pending 后不再保留第二份引用。
- 未完成的构造、已取消的上传不缓存，超出预算的密集近景仍需重建。首次进入从未生成的区块不因此加速。

## 固定输入对照

脚本：`scripts/benchmark-v6-tree-cache.cjs`。原始记录：`benchmarks/v6-tree-cache-20261107.json`。

基线从 Space 中完整 `b8a8f7f` 源码独立编译，不是运行时关闭缓存来冒充旧版。两版都使用 seed 42173 的同一份真实 terrain6 状态（1685 棵保存树），每帧最多构造 24 棵、上传 262144 字节，时间上限设为 Infinity，消除机器负载对工作计数的干扰。镜头序列是合成的区块中心 8×8 视域，不是用户录制轨迹，不修改全岛尺寸。

- 近景 `8:3 → 10:6 → 8:3`：回到 A 时，重复构造 **15 棵 → 0 棵**。回访上传仍为 **489672 字节**，达到稳定状态的推进调用仍为 2 次。新增非活跃缓存峰值记账 3291490 字节。
- 同一远景序列：回访重复构造 **15 棵 → 0 棵**；上传仍为 **63720 字节**，推进调用仍为 1 次。缓存峰值 324756 字节。
- 超大近景对照 `7:3 → 8:3 → 7:3`：A 的 67 棵树批次超过缓存额度，回访仍重建 **67 棵**，上传仍为 **3029232 字节**。缓存不通过越过额度来制造命中。
- 复用有验证成本：近景回访的高度采样由 15 次变 45 次，远景由 15 次变 30 次（查询缓存时及每次待上传推进均校验），换取不再变换/合并每棵树的顶点、法线、颜色和拾取数组。本次没有测端到端耗时，不将构造量下降直接称为帧率提升。
- 每一阶段完整网格的属性/索引/边界 SHA-256 与基线相同，树 ID、拾取边界和树脚射线结果 SHA-256 相同。保存状态逐字节不变；所有模拟 GPU 网格均恰好销毁一次，最终缓存记账归零。

## 验证

新增 11 项短测覆盖回访、字节/条目上限、超限、关闭缓存、成长/砍树/位移/身份、种子、LOD、实际树脚高度变化、等待地面/上传、取消、销毁及小预算下的 A/B/A 优先级。连同受影响高程与反馈短测，23/23 通过。对实际 `V6TreeView` 和 `V6ChunkMeshes` 的检查使用 Cocos 调用替身，不是替换生产引擎。

独立只读审查未发现具体缺陷，最后补充的回访优先级逻辑也单独复核通过。仓库要求的完整检查及 demo 结果记录在本次交付的验证摘要中。

未运行 Creator 编辑器、WebGL 实际图像、GPU、Android 或手机测试，未推送或部署。本改动解决的是可缓存区块的 CPU 回访重建；首次生成、密集区块与实际设备表现仍需后续工作。

复现：先分别编译原整合源码和本版本，再设置 `V6_TREE_BASELINE_BUILD` 为原源码的 `.domain-build` 绝对路径，执行 `node scripts/benchmark-v6-tree-cache.cjs`；`V6_TREE_BENCHMARK_OUTPUT` 可指定 JSON 输出位置。
